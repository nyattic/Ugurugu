2.2.0 makes the canvas faster to display and strengthens selection, recovery,
and export reliability.

## Improved

- The canvas display now uses the GPU. Panning, zooming, and animation
  playback no longer make the CPU rescale the whole view, so they respond more
  smoothly. The app automatically returns to the existing software display
  when graphics acceleration is unavailable.
- Preview frames are prepared several at a time, and computers with plenty of
  memory can keep more of them ready. After a stroke, only the changed region
  is refreshed instead of rebuilding every frame from scratch, so playback
  settles more quickly.
- Wacom WinTab input is now supported on Windows. Installing the Wacom driver
  enables pen pressure on systems where it was not reported correctly before.
- A layer whose eraser marks overlap the artwork underneath can now be merged
  down without changing how the picture looks. A new eraser stroke after the
  merge reaches the whole combined layer. Merges that cannot preserve the
  result, such as one involving a canvas resize, are still refused with an
  explanation.

## Fixed

- With wobble playback switched off, per-layer wobble stopped on the canvas
  but could still shift the colour sampled by the eyedropper or the picture
  exported as PNG or JPG. Sampling and still-image export now match what is on
  screen.
- Creating a document or opening another file in the middle of a stroke or an
  area selection could put the unfinished input into the replacement document
  when the pen was lifted. Replacing a document now safely cancels live input.
- Canceling an area selection after its mode or the canvas size changed could
  discard the selection that existed before it. That previous selection is
  now restored correctly.
- Move mode left armed by a copied selection could unexpectedly activate on a
  different selection made later.
- Scrubbing between frames could leave stroke-property editing disabled when
  editable strokes were inside the selection, or enabled when none were.
- Changing a selection repeatedly could leave obsolete visibility checks
  running and make the app slow down. Superseded checks are now canceled.
- Animation export underestimated the memory needed by documents with deeply
  nested layer groups. The export dialog now includes the document hierarchy
  when choosing the largest scale that can be handled safely.
- When recovery saves overlapped, completion of an older save could be mistaken
  for completion of the newest one. If the newest write then failed, it was not
  retried and the recovery file could fall behind the drawing.
- An unexpected failure in background export, recovery saving, or the Windows
  update check could close the app. The operation now finishes as a failure so
  it can report the error or retry the next recovery save.
- Opening a shorter animation could move the canvas to a valid frame without
  moving the timeline from the old frame.
