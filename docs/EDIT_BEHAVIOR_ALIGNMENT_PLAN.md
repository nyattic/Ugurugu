# WWP 편집 동작 정렬 계획

## 1. 목표

WagleWaglePaint(이하 WWP)의 편집 동작을 Clip Studio Paint(이하 CSP) 관례에 맞춘다.

WWP 1.0.0은 그림 도구의 일반적인 관례와 다르게 동작하는 지점이 있다. 대표적으로 선택 영역 복제가 같은 레이어에 결과를 쌓고, 클립보드 복사·붙여넣기가 아예 없다. 이 계획은 그런 지점을 찾아 CSP 관례로 옮긴다.

이 문서는 `WIGGLE_INTEGRATION_PLAN.md`와 **별개 작업**이다. 저쪽은 없던 기능을 더하는 일이고, 이쪽은 이미 출시된 동작을 바꾸는 일이다. 사용자에게 보이는 변경이므로 릴리스 노트와 공지가 따로 필요하다.

> 현재 상태: 단계 A와 B는 구현·테스트·3개 언어 릴리스 노트까지 완료됐다. 3장의 표는 v1.0.0 감사 기록이고, 단계 C의 변형 핸들만 별도 재평가 대상으로 남아 있다.

### 반드시 유지되는 것

편집 동작을 바꾸는 것이 렌더 결과를 바꾸는 것을 뜻하지 않는다. 이 둘은 끝까지 분리한다.

- 기존 `.wagle` 파일은 v1.0.0과 **픽셀 단위로 동일하게** 렌더된다
- 문서 모델, 직렬화, 결정론적 렌더 경로는 이 계획의 범위가 아니다
- 새 동작이 `Stroke`나 `Layer`의 의미를 바꾸지 않는다

이 계획에서 바뀌는 것은 **사용자가 무엇을 했을 때 문서가 어떻게 변하는가**뿐이다.

### 범위 밖

- 단축키 배치, 도구 이름, 패널 구성
- CSP의 기능 자체를 옮겨오는 일 (레이어 마스크, 색조 보정 레이어, 3D 데생 인형 등)
- 렌더 알고리즘과 파일 형식

단축키와 UI는 별도 판단이다. WWP는 이미 `ShortcutBinding`으로 사용자 재지정을 지원하므로 기본값 변경은 급하지 않다.

## 2. 판정 기준

각 차이를 셋 중 하나로 판정한다.

| 판정 | 뜻 |
| --- | --- |
| **정렬** | CSP 관례로 바꾼다 |
| **유지** | WWP 현재 동작이 맞거나 더 낫다. 바꾸지 않는다 |
| **보류** | 판단에 실물 확인이나 사용자 피드백이 필요하다 |

"CSP가 그렇게 하니까"만으로는 정렬 사유가 되지 않는다. 사용자가 다른 도구에서 익힌 기대와 어긋나서 실수하게 만드는지가 기준이다.

## 4. 확정 변경 목록

3장의 **정렬** 판정만 모은 것이다. 보류 항목은 포함하지 않는다.

1. 클립보드 복사 (`Ctrl+C`) — 선택 영역의 내용을 클립보드로
2. 클립보드 잘라내기 (`Ctrl+X`) — 복사 + 원본 삭제
3. 클립보드 붙여넣기 (`Ctrl+V`) — **새 레이어**에 붙여넣기
4. 선택 영역 복제를 새 레이어로 변경 — 또는 클립보드로 대체하고 제거
5. 선택 더하기 (`Shift` + 드래그)
6. 선택 빼기 (`Alt` + 드래그)
7. 전체 선택 (`Ctrl+A`)
8. 선택 반전 (`Ctrl+Shift+I`)
9. `Ctrl+D`를 선택 해제로 재배치 (4번 결과에 따라)

## 5. 설계 시 결정할 것

### 결정 1: 복제를 고칠 것인가 없앨 것인가

4번은 두 갈래다.

- **고친다**: `Ctrl+D`를 유지하되 새 레이어에 복제한다. 기존 사용자의 동작이 이어진다
- **없앤다**: 복제를 빼고 복사 → 붙여넣기로 대체한다. CSP와 완전히 같아지고 `Ctrl+D`가 선택 해제로 비워진다

후자가 관례상 더 맞지만 기존 기능을 제거하는 것이므로 사용자 영향이 크다. 실물로 두 흐름을 다 써 본 뒤 정한다.

**결정 완료:** 별도 복제 액션을 제거하고 `Ctrl+C`가 선택 내용을 새 레이어와 클립보드에 함께 배치하도록 했다. `Ctrl+D`는 선택 해제로 재배치했다.

### 결정 2: 클립보드에 무엇을 담을 것인가

WWP의 레이어는 비트맵이 아니라 스트로크 벡터와 ordered op의 나열이다. 따라서 "무엇을 복사하는가"가 자명하지 않다.

- **스트로크를 복사한다**: 붙여넣은 뒤에도 흔들리고 편집 가능하다. WWP다운 선택이지만 외부 앱과 주고받을 수 없다
- **래스터를 복사한다**: 외부 앱과 주고받을 수 있지만 붙여넣은 내용이 흔들리지 않는 죽은 픽셀이 된다

**두 형식을 동시에 담는 방향을 우선 검토한다.** WWP 안에서 붙여넣으면 스트로크가 살아 오고, 외부 앱에 붙여넣으면 래스터가 간다. `QMimeData`가 여러 형식을 함께 담을 수 있으므로 구조상 가능하다.

외부에서 들어온 래스터를 붙여넣는 경우는 `WIGGLE_INTEGRATION_PLAN.md` 결정 D의 raster asset이 있어야 제대로 처리된다. **그 전까지는 외부 래스터 붙여넣기를 지원하지 않고 명확한 안내를 낸다.**

**결정 완료:** 내부 스트로크 형식과 외부 앱용 래스터를 동시에 기록한다. WWP 내부 형식을 우선해 붙여넣고, 외부 래스터만 들어오면 Insert Image 기반이 생길 때까지 명확히 거부한다.

### 결정 3: 레이어 한도

`DocumentLimits::maximumLayers`는 256이다. 붙여넣기와 복제가 매번 새 레이어를 만들면 반복 작업에서 이 한도에 훨씬 빨리 닿는다. CSP는 실질적으로 메모리 한도까지 열려 있다.

한도를 올릴지, 아니면 한도에 닿았을 때의 안내를 개선할지 정한다. 올린다면 `LayerDock`의 목록 성능과 `LayerCompositionPlan`의 표면 개수 추정을 함께 확인한다.

**결정 완료:** 256 한도를 유지하고, 한도나 문서 예산을 넘는 붙여넣기는 문서를 바꾸지 않은 채 명확히 거부한다.

### 결정 4: 선택 더하기·빼기와 기존 수식자의 충돌

`Alt`는 현재 스포이드다(`CanvasWidgetEvents.cpp`). 선택 도구를 쓰는 동안에만 빼기로 해석하고 그 외에는 스포이드를 유지하는 방식이 자연스럽지만, 도구별로 같은 키가 다르게 동작하는 것이 혼란스러울 수 있다. 실물 확인이 필요하다.

**결정 완료:** 선택 도구에서만 `Alt`를 선택 빼기로 사용하고, 다른 그리기 도구에서는 기존 스포이드 동작을 유지한다.

## 6. 호환성과 사용자 영향

- **파일 호환성 영향 없음.** 문서 모델과 직렬화를 건드리지 않는다
- **렌더 결과 영향 없음.** 기존 `.wagle`은 v1.0.0과 동일하게 렌더된다
- **동작 변경 있음.** `Ctrl+D`를 쓰던 사용자는 결과가 달라진 것을 즉시 느낀다

동작이 바뀌는 변경이므로 릴리스에서 다음을 지킨다.

- 릴리스 노트에 바뀐 동작을 한국어·영어·일본어로 명시한다
- 복제 동작이 바뀌었다면 첫 실행 시 한 번 안내한다
- 최소 한 번의 마이너 릴리스 동안 이전 동작을 설정으로 되돌릴 수 있게 할지 결정 1과 함께 정한다

## 7. 구현 단계

### 단계 A: 클립보드 기반

예상 기간: 2~3주

- [x] `QMimeData` 형식 정의 (WWP 스트로크 + 래스터)
- [x] 복사, 잘라내기, 붙여넣기
- [x] 붙여넣기가 새 레이어를 만들고 활성 레이어를 수정하지 않음
- [x] 레이어 한도·깊이 한도에 걸린 붙여넣기가 문서를 바꾸지 않고 거부
- [x] 외부 래스터 붙여넣기에 대한 명확한 미지원 안내
- [x] undo·redo·자동 저장·복구 경로 통합

종료 조건:

- 복사한 스트로크가 붙여넣은 뒤에도 흔들리고 편집 가능함
- 붙여넣기가 실패해도 문서가 부분적으로 바뀌지 않음
- 외부 앱에 붙여넣으면 래스터가 정상적으로 전달됨

### 단계 B: 선택 관례

예상 기간: 1~2주

- [x] 전체 선택, 선택 반전
- [x] 선택 더하기 (`Shift`), 선택 빼기 (`Alt`)
- [x] 결정 4의 수식자 충돌 해소
- [x] 선택 영역 복제 처리 (결정 1)
- [x] `Ctrl+D` 재배치

종료 조건:

- 더하기·빼기가 기존 선택 마스크 모델 위에서 동작함
- 선택 관련 undo 항목이 개별적으로 되돌려짐

### 단계 C: 보류 항목 재평가

3.3의 변형 핸들을 실물로 평가하고 별도 산정한다. 단계 A와 B가 끝나기 전에는 착수하지 않는다.

## 8. 테스트

- 붙여넣기·복제가 활성 레이어를 절대 수정하지 않을 것
- 레이어 한도에 걸린 붙여넣기가 문서를 전혀 바꾸지 않을 것 (원자성)
- 복사 → 붙여넣기 후 스트로크의 seed와 흔들림이 보존될 것
- 잘라내기 후 undo가 원본을 정확히 되돌릴 것
- 더하기·빼기 선택이 기존 마스크 직렬화와 호환될 것
- 클립보드가 비어 있거나 알 수 없는 형식일 때 안전하게 거부할 것
- **기존 `.wagle` 문서의 렌더가 v1.0.0 골든과 동일할 것** — 이 계획 전체에 걸쳐 유지
